# 全栈重建（进行中）

此目录是新实现的 TypeScript 单体仓库；旧 Java/Vue 2 实现暂时保留在上层目录，仅作行为和历史数据参考。**尚未达到旧版功能等价，也不要把它用于生产记账。**

## 技术基线

- Node.js 24 LTS（本地至少 22.12；Vite 8 要求 20.19+ 或 22.12+）
- NestJS + Fastify API，Vue 3 + Vite + TypeScript 前端
- MySQL 8.4，Kysely typed SQL / migrations
- 财务数额在数据库中使用 `DECIMAL`，应用层使用十进制字符串和 `decimal.js`

直接依赖暂按 2026-10 的稳定版本锁定，更新前需执行构建和回归测试。

## 明确移除的范围

新实现不提供短信发送、短信验证码、注册、密码登录、用户密码表或内置身份认证；相应的应用模块和依赖不会迁入。初期按单机/受信任内网工作区设计，API 默认只监听 `127.0.0.1`。**不要通过设置 `HOST=0.0.0.0` 将无认证服务暴露到公网。** 如未来需要远程多用户访问，必须另行设计受信任的外部身份边界和权限方案；“没有认证”不代表可以公开访问。

这不等于旧 Java 程序里的登录/短信已经从旧代码删除。重建未完成前，旧服务仍保留作参考，不能把旧服务当成已被本目录替换。

## 本地运行

```bash
cd rebuild
npm install
cp .env.example .env
docker compose up -d mysql
npm run db:migrate --workspace @financial/api
npm run dev
```

- 前端：<http://127.0.0.1:5173>
- API 存活检查：<http://127.0.0.1:8080/api/v1/health>
- API 就绪检查（需要数据库）：<http://127.0.0.1:8080/api/v1/health/ready>

Compose 中的账号密码只用于本机开发。生产环境不得使用示例凭证。

## 当前实现范围

- 已实现账套列表、读取和创建；创建账套时按会计制度导入企业或小企业科目模板，并建立当前期间。
- 已实现科目列表、新增、导入模板、期初余额维护和安全删除检查。
- 已实现凭证草稿创建/编辑/删除及借贷平衡校验后的记账；记账凭证不能直接修改或删除。
- 已实现按已记账凭证和期初余额计算试算平衡表、总账汇总和末级科目明细账。
- 已实现基于旧版科目映射模板的利润表；资产负债页面目前是按科目类别汇总的预览，**不是已完成旧版行项目映射的法定格式报表**，需会计复核。
- 已实现会计期间列表、期间锁定/推进和最近期间反结账；目前**不会自动生成损益结转凭证**，不能视为完整月结/年结。
- 迁移建立账套、科目、会计期间、凭证和分录表；没有用户、密码或短信表。金额字段是 `DECIMAL(24,8)`，正式确定精度前仍需会计规则评审。
- 现金流量表、辅助核算、凭证审核/反记账、完整结转与月结、旧版自定义报表、打印导入导出及旧库数据转换等功能仍待迁移。不要把旧 `financial.sql` 直接导入本目录数据库；先生成映射方案、备份和对账报告。
